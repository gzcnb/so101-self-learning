# 从真机试错到可复用技能

本项目要研究的核心问题是，SO-101 能否在没有人工任务示范的条件下，通过自己的真实交互，逐渐提高操作成功率，并将改进保存下来供下一次任务调用。

本文区分当前代码与计划设计。文中的统一经验格式、任务策略训练、自动重置和技能版本管理属于待实现部分，对应 [任务 #1](tasks/01-autonomous-learning.md)。

## 为什么需要这条学习链路

文字指令描述目标，真实操作还取决于夹爪接触、舵机跟踪、视觉误差和物体运动。以叠放为例，抓到橙块、把橙块移到灰块上方、松开夹爪、退出后仍保持叠放，分别有不同的失败原因。

当前实验出现过固定爪退出时带落橙块的情况。这条经验只有在影响后续动作时，才产生学习收益。系统应能将“退出后倒塌”的证据关联到释放与退出阶段，调整适用的动作参数，再检查调整是否提高了完整任务的成功率。

经验被保存后，还应能够支持下一轮训练、故障分析和版本比较。随着任务增加，工程投入应更多用于通用感知、执行和学习机制。逐个任务的人工调参量能否减少，是这个方向需要验证的价值。

## 当前哪些部分会变化

| 对象 | 当前更新方式 | 保存与复用现状 |
| --- | --- | --- |
| 关节补偿 | `learning/rls.py` 根据参考和实测关节位置更新 RLS 权重与协方差 | 类内存中更新，尚无该类的检查点保存与加载接口 |
| 叠放落点 | `WorkbenchPlanner.stack_feedback()` 根据松爪前视觉误差，按限幅规则更新平面偏差与释放高度 | `SwapMission.run_stack()` 保存到运行目录下的 `stack_fit.json`，底座位置变化较大时停用旧修正 |
| 抓取偏差 | `pickup_feedback()` 按腕部画面和夹爪覆盖情况修正本轮偏移 | 用于有限次数的重试，尚无跨任务策略训练 |
| 换位进度 | `pending.json` 保存任务阶段与现场信息 | 重新观察现场后决定是否续跑，属于任务恢复状态 |
| 视觉动作策略 | 已发布 CNN 编码器与 GRU 策略网络定义 | 训练入口、数据和可复用权重仍需补齐 |

这些机制承担不同职责。后续报告会分别展示控制补偿、规则参数修正和任务策略学习的贡献，保留每项更新的证据。

## 大模型的监督职责

### 已实现的监督

`workbench/swap_skill.py` 中的 `verify_identity()` 将用户指令、固定相机画面和视觉候选一起交给 Qwen，要求返回受限 JSON，确认操作类型及橙色、带圆纹深灰色两个目标。目标不明时停止当前任务。

`verify_stack_result()` 对叠放区域截图进行核验，询问橙块是否由灰块支撑。执行流程还检查视觉定位、板端结果与退回状态。单个视角下的支撑关系仍可能被误判，当前记录尚未证明该判据的可靠性。

Qwen 在桌面端通过 `llama.cpp` 调用部署者准备的 VL 权重。原型使用过 Qwen3-VL 系列，具体量化、设备和运行时版本需随实验记录。

### 为自主学习补充的监督

计划让监督结果覆盖以下内容，并关联原始证据。

| 监督内容 | 需要核对的事实 | 对学习的用途 |
| --- | --- | --- |
| 任务目标 | 操作哪两个物体，最终应满足什么关系 | 形成固定的本轮任务定义 |
| 阶段进展 | 是否夹住、是否搬运到位、是否已释放 | 提供阶段标签，帮助定位失败 |
| 完整结果 | 夹爪离开、机械臂退回后，目标关系是否仍成立 | 生成任务终态标签 |
| 失败分类 | 空抓、途中掉落、释放滑落、退出带落、遮挡、通信中断 | 选择可调整参数或恢复方式 |
| 证据充分性 | 图像是否清楚，多次观察与状态是否一致 | 决定样本能否用于相应训练目标 |

大模型推断的失败原因需要保留为待验证假设。例如，画面里看到橙块倒下，可能与固定爪接触有关，也可能是原本就没有放稳。恢复与学习应优先依据可观察到的阶段变化。

奖励和标签需要独立于策略意图进行检查。策略说“已完成”或控制程序正常退出，都不能单独构成成功标签。图像遮挡、双视角冲突或状态不完整时，样本保留“无法确认”，不给予未经证实的成功奖励。也要保留被模型判成功但物理结果失败的样本，用于检查监督器本身的错误。

### 监督器与控制器的边界

模型推理可以安排在观察、抓取后、释放后和退出后等阶段。舵机实时通信与关节保护在板端运行。监督器只能请求已注册的观察或操作能力，动作需要通过确定性的工作区、关节与步长检查。

学习器也遵守这些检查。后续统一板端控制入口后，网页、训练器和研究脚本共享同一执行权，所有动作带任务编号与来源。大模型的解释不会替代控制权检查。

## 零人工示范训练协议

目标协议允许预训练视觉语言模型、硬件标定、人工定义的动作原语和成功判据。任务训练数据来自机械臂自己的尝试，人工成功轨迹与遥操作接管需要单独标记，不能混入零示范训练集。

当前流程使用了实测参考姿态，因此现有结果还依赖具体工位的工程先验。后续实验必须列出这些先验，并说明学习器自行获得的是补偿、动作参数还是整个任务策略。

人工把掉落物体摆回去属于训练重置，需要统计次数与耗时。它降低了自主程度，也决定训练能否持续运行。需要人工重置的训练阶段可以先开展，但公开结果必须说明这一条件。

## 推荐先实现的学习路线

第一阶段围绕现有动作原语学习小范围调整。这样可以把真实交互集中用于接触与释放阶段，并先验证数据、反馈和模型保存是否连通。

1. 固定已标定的工作区、几何控制器、原语和保护规则，保存初始版本作为基线。
2. 定义少量可调参数，包括抓取平面偏移、夹爪朝向、释放高度、分离距离和已检查的退出路径选项。明确每个参数的单位、范围和有效条件。
3. 先用有边界的参数搜索建立可复现基线。每次从当前观察选择一次尝试，执行、记录结果，再更新参数选择模型。避免一次改变过多因素，使失败难以归因。
4. 保存本次模型、经验数据索引和随机状态。下次任务重新定位目标后加载模型，检查适用工作区和物体条件。
5. 冻结候选版本，在独立布局上评估。通过预先约定的标准后才成为默认技能，失败则保留原版本。

这一阶段得到的是基于既有原语的参数选择能力。之后可以引入基于视觉和关节状态的残差策略，学习连续动作修正。需要稳定的交互接口、回放数据和奖励后，再评估 SAC 等离策略方法，或引入世界模型方法。

[DreamerV3](https://github.com/danijar/dreamerv3) 从经验学习世界模型，并在模型生成的轨迹中训练策略。它可以作为后续算法候选。本项目仍需先实现真实环境接口、可靠的反馈、重置与评估。具体算法在 SO-101 上的收益需要实验比较。

[SERL](https://serl-robot.github.io/) 提供真实机器人离策略学习、奖励定义和控制基础设施方面的参考。本项目的零示范要求需用自己的数据协议核验，其他平台的结果不能直接作为本机械臂的效果承诺。

## 每次尝试需要保存什么

下面是拟定的经验记录要求，后续实现时需要形成带版本的数据格式。

| 类别 | 必需内容 |
| --- | --- |
| 身份与版本 | 任务、回合、步骤编号，时间，代码、标定、策略、监督器与提示词版本 |
| 观察 | 动作前后的固定及腕部图像，关节状态，目标定位，缺失或过期标记 |
| 动作 | 请求动作、实际下发动作、参数、执行时长、被保护器截断或拒绝的原因 |
| 结果 | 阶段结果、终态结果、奖励项、证据引用、失败类别、是否无法确认 |
| 人工介入 | 重置、接管、摆动物体、修改代码或参数的时间与原因 |
| 更新关系 | 本轮使用的策略版本，数据参与的训练批次，产生的新版本和评估状态 |

成功、失败、保护中止和无法确认都需要保存。图像、动作与关节状态要有可检查的时间关系。通信中断与真实任务失败分别记录，避免用不完整数据训练出错误关联。

统一经验库尚未实现，现有 `report.json`、`pending.json` 与 `stack_fit.json` 提供部分信息，可以作为迁移来源。

## 把一次叠放变成可持续的训练回合

| 阶段 | 需要观察什么 | 失败后如何处理 |
| --- | --- | --- |
| 识别 | 目标身份、底座与可达区域 | 目标不明则结束，保留原始画面 |
| 抓取 | 夹爪覆盖与提起后物块是否随动 | 能确认物块仍在可达区时重新定位，否则结束 |
| 搬运 | 物块是否保持夹持，底座是否移动 | 掉落后复查现场，满足恢复条件才继续 |
| 对齐与释放 | 顶面关系、释放前后位置变化 | 保留连续证据，关联本轮释放参数 |
| 分离与退出 | 夹爪是否碰动物块，退出后是否倒塌 | 将退回后的结果用于完整任务验收 |
| 重置 | 物块位置、夹爪状态、当前执行权 | 在已检查区域恢复起始布局，无法恢复时结束并记录 |

恢复动作也需要训练与验收。对象靠近边缘、夹爪仍持物或布局不清时，不能直接复用旧抓取点。下一轮动作必须依据重新观察的现场状态。

## 学到的技能如何复用

计划保存的技能版本需要包含任务适用条件、动作策略或参数模型、所需标定、依赖原语、评估报告与可回退的上一个版本。每次加载后重新识别现场，在适用条件内执行。

任务进度与技能版本分别保存。换位进行到第二步的记录帮助恢复本次任务，经过独立评估的策略版本帮助完成下一次任务。两类记录都需要持久化，并在文档和接口中说明各自用途。

## 验收方法

训练前确定工作区、物块、起始布局范围、回合超时、恢复次数限制、成功判据与物体稳定观察时长。叠放成功要求夹爪完全分离、机械臂退回后物块仍稳定，并保留终态证据。

固定基线与候选策略使用相同的评估条件和试验预算，随机交错测试顺序，单独预留训练未使用的布局。评估阶段冻结策略并记录是否还存在在线适应。试验数量与停止规则在运行前确定，报告成功数与总数、统计不确定性、交互耗时、恢复、重置和接管情况。

至少验证三种情形，分别是同布局重复、新布局测试和进程重启后加载。还要检查监督器误报，避免把视觉重叠或短暂接触记为稳定叠放。当前数据量不足以给出可靠的任务成功率或学习收益结论。
